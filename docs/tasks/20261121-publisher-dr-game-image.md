# 发布器故障与游戏灾备镜像

本批修复现行发布器故障，并增加游戏正式发版达到终态后的镜像灾备。先核对故障记录、发布状态和现有镜像传输方式，再确定最小改动及验证范围。

完成条件为现行故障有可复现回归，成功发版冷备准确镜像、确认到达后清理灾备机其他游戏镜像、保留最近一版且不启动容器。覆盖提前触发、同步失败、重试与其他镜像隔离。通过项目门禁后上线发布器。真实灾备验收留待下一次游戏发版。本批不启动游戏或论坛发版，不修改应用仓库、业务数据或计划任务。

基线为 `4731235`。原工作树已有其他任务的未跟踪文件，保持原状。正式验证前记录受影响文件、直接消费者、验证命令、预计耗时和停止条件。

## 故障证据与实施范围

线上 `3bed315` 空闲。20261121 游戏计划预览返回 HTTP 400，三个未评估路径与 2026111701 已发布差异一致。历史记录保留 SSH 断连和回滚未提交的结果；环境归档 `rhospital/docs/evidence/bacteria-plan-classification-release-20261117/ENVIRONMENT.md` 和游戏候选目录的 `PRODUCTION_EXECUTION.json`、`POST_DEPLOY_COMPLETION.json` 证明了确切目标、旧任务退出、后续四项验收通过。将这笔已复核生产身份纳入基线匹配，保留历史与严格评估。

灾备目标为已有 B 节点 GreenCloud。复用固定目标、严格主机校验及 `/etc/rhospital-ha/stage.lock`。生产已验收后核对其健康容器的镜像 ID，传输后核对 B 的归档校验及镜像 ID，清理本库旧标签并回读。灾备失败显示于步骤与历史，线上游戏终态不参与回滚。无标签且无法判定归属的对象及容器不作任何清理。

Sub2API 模型目录连接两次失败。采用主 Agent 复核，未向外部提供仓库内容。

## 验证冻结

本批仅包含 `src/releasePublisherCore.js`、`test/releasePublisherCore.test.js`、变更日志、操作手册、双节点说明及本记录。直接消费者为生产基线比较、计划和通用步骤渲染、运行状态及历史持久化。原生提交验证负责 documents、publisher-plan、publisher-source、publisher-console、publisher-recovery；预计两分钟，超过两分钟报告原进程，继续按门禁的既有超时执行。推送只核对提交、覆盖和有效证据。通过后执行现有发布器更新器，核对空闲、运行身份及只读游戏计划；不执行生产发布。首次真实灾备传输与清理留给下一次正式发版。

定向调试失效输入依次为嵌套 PowerShell 参数传递、Windows PowerShell 5.1 缺失的哈希命令，以及测试脚本同时解码了 A 和 B 两端。前两项修复后 Windows 替身传输通过，后续由原生门禁一次覆盖当前候选。线上 `/api/remote-tag` 确认 `hospital-backend:2026111701`。

原生首检 documents PASS，Console 拒绝未注册的新步骤。只增加现有流程的「灾备镜像」阶段映射与回归断言，调整步骤在计划中的展示顺序；不改布局、控件和样式。失效输入为 Core 的步骤顺序、Console 的映射与断言及本记录；最小重跑为原生提交门禁，继续既定分组。固定桌面 1440×900、手机 390×844 与最窄 320×800，复用现有控件，检查可操作热区、实际文字与框边余量、主页面无横向溢出和步骤详情。通过本机隔离控制台验证，独立记录截图、功能、几何与视觉，再启用服务。

第二次原生验证的 Console 与 Recovery 通过。Plan 为 162/163，新功能与基线回归全部通过，唯一失败来自原有分支选择测试结束时 Windows 拒绝删除其专属 Git fixture，错误为 EPERM。失效项仅为 Plan 的执行条件，消耗 Git 临时目录；Doc 记录变更后静态重验，Console 和 Recovery 按回执复用，Source 尚未运行。最小重跑为原生提交，使用新的本任务专用临时根，旧 fixture 保留供本批收尾核查。

移到新的临时目录后，原生 Plan 仍有 Git fixture 清理 EPERM，残留包含只读 Git 对象；相关失败测试单独运行可通过。核对 Node 官方 Windows 只读文件删除问题 [#64374](https://github.com/nodejs/node/issues/64374) 后，改用本机已有的 Node 24.22.3 执行原生提交和推送，运行时选择只作用于门禁进程，原生钩子和应用配置原样保留。由于门禁身份包含 Node 版本及执行文件，旧运行环境回执不可复用，仍只执行原冻结分组。
