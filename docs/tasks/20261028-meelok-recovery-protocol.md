# Meelok maintenance recovery safety

This patch preserves the established formal game-release pause/restore strategy. It neither adds a business dependency on Meelok nor lowers the 2 GiB cutover / 1.5 GiB restore memory gates. Game outcomes and rollback decisions remain authoritative and separate from an unresolved companion-maintenance result.

New maintenance generations keep their actual captured replica/image snapshot in the compose directory's `.publisher-maintenance/<UUID>/`, outside ordinary release-backup rotation. `rollback-backup.ref` and the original backup's `.publisher-maintenance-pin-<UUID>` identify rollback assets that must be retained. The publisher has no backup-root deletion/rotation implementation; external operators and cleanup tools must honor these pins. This does not prevent an administrator deliberately removing files. Missing legacy snapshots are not reconstructed or invented.

Pause and restore share a nonblocking remote flock. Capture and marker persistence precede pause mutations. Recovery persists ATTEMPTED before launching a separate GNU timeout process group (2100 seconds, TERM then KILL after 5 seconds), beneath the existing 2400-second local transport deadline. Scale requests use detach and existing explicit readiness polling. Phase and outcome logs distinguish a hung CLI/transport from confirmed completion; killing a CLI does not prove a Swarm mutation was cancelled.

An unsuccessful or lost result remains UNKNOWN/ATTEMPTED, retaining marker, snapshot and pins. It cannot automatically replay. Operators must first reconcile actual tasks, images, process ownership and the saved generation; the publisher does not kill historical processes or take ownership of older records. Saved pre-protocol commands are not automatically run on restart/controlled recovery. Old production maintenance restoration belongs to its operations task.

Only the owning recovery under the shared lock may archive its marker after all original services satisfy readiness and the captured snapshot hash still matches. Marker contents and snapshot identity are checked before terminal archive. The archive and VERIFIED state are retained; subsequent verified invocations are nonmutating and check retained evidence. UNKNOWN, foreign ownership and incomplete terminal evidence refuse replay. No snapshot, image package or rollback backup is deleted by this patch; retiring pins requires separately verified terminal ownership and asset-dependency review.

An unresolved restore is recorded as a failed maintenance step with recoveryOutcome UNKNOWN and a separate recovery-required flag, not falsely marked done. It does not turn a successful game deployment into an automatic game rollback. Original game results and immutable history remain unchanged.

Verification uses only temporary Git-Bash fixtures, Docker/service doubles, synthetic state and a bounded native timeout process group. Existing unrelated check evidence is reused. No game or Meelok production operation is part of this repository's verification. UI styling is unchanged. GNU timeout, flock, sync and Bash availability are explicit prerequisites; unavailable prerequisites fail closed before issuing recovery mutations.
