# 应用发布策略 v1

游戏应用在精确提交中拥有 `release/publisher/game-policy.json`，协议为 `application-release-policy/v1`。字段由 `src/applicationReleasePolicy.js` 的闭合校验定义，完整实例由应用仓库维护。论坛继续使用原有独立流程。

| 内容 | 所有者与消费方式 |
| --- | --- |
| 业务源码位置、Catalog 标记、镜像类和字段索引约束 | 应用声明，发布器读取候选并核对实际镜像 |
| 格式迁移组合、兼容类、格式底线、调度执行器和观察 SQL | 应用声明，通用迁移和恢复消费者保留备份、互斥、幂等、现场身份及版本 CAS |
| 数据库业务审计 Java、调度 Python、只读和回滚前 SQL | 应用 `inputs` 内的真实源文件，精确候选读取与哈希绑定 |
| 启动日志、业务探测和 Catalog 发布结果 | 应用 shellChecks 文件；受限命名占位符由发布器绑定，不允许未绑定占位符静默留下 |
| 静态加载场景、关系图、急救防刷 | 应用 Node 程序及其测试，通用私有导出执行入口 |
| 浏览器 CDP、进程与临时目录生命周期 | 发布器 `release-browser-host/v1` API，应用显式导入受控绝对路径 |
| 页面就绪与业务心跳 | 应用表达式及类型化 heartbeat 声明，发布器执行并核对结果 |
| 锁、凭据来源、固定安全步骤、数据库目标、镜像恢复身份、回滚阈值和生产授权 | 发布器及环境配置，应用检查不能替换固定步骤 |

## 身份与失败协议

计划固定候选40位提交。profile 原始摘要单独记录；`ownedInputHash` 对声明及拥有文件的 UTF8 LF 文本构成闭包。读取使用 Git 对象，工作区脏文件不能改变执行内容。缺少声明、源文件、类、表达式或未知协议立即拒绝，不加载旧内置业务代码。

应用 Node 检查从同一候选导出 profile 和声明输入到私有目录，清除发布器认证环境；argv 由受控绑定给出。退出码、终态 marker 或 `check-result` JSON、超时及输入字节完整性共同决定结果。进程成功且缺少协议仍失败。命令显式携带候选、策略闭包摘要、检查ID和入口提示。输出只交付已核验摘要，不转发可能包含凭据的原始业务日志。

`runtimeChecks` 可声明 `http-get` 或 `node-check`，ID 使用 `application.*` 命名空间。路径和前缀供应用准备资材时描述影响，正式计划只选择发版影响评估 `requiredChecks` 显式列出的业务运行检查。Node 检查引用 nodeChecks，并通过受支持的字面参数或 `$appTag`、`$authTokenFile`、`$browserHost`、`$sshTarget`、`$sshKey`、`$sshPort` 参数绑定使用既有能力。浏览器检查由发布器传入与静态分发一致的环境清单。固定 final-runtime-check 先执行，声明的清理在业务检查之后。未知检查拒绝进入计划。

历史三项业务步骤ID保留为外部资材公开契约，具体实现与影响映射均由应用声明。普通新业务直接使用 runtimeChecks，无须增加历史ID。历史失败回执保留原身份；补充核验要求原候选拥有可解析策略，缺少时保持缺证据，不能拿当前策略替换旧候选。

OCI 索引/清单、配置ID、平台、有序层和归档SHA256分别记录。准备工具仅在平台、配置及有序层一致时给出产物内容等价；该结果不修改源码证据、原归档或现场安全结论。

## 准备与升级

应用的 `scripts/validation/release/prepare-plugin.mjs` 使用已有 esbuild 和 Rollup 收集静态 import、相对 require、传递文件及已安装的可选依赖。动态文件访问仍须 extraInputs 显式声明。产出既有 run-leaf/check-result-v1 协议，检查策略Node闭包、就绪表达式、精确基线运行差异和迁移集合。

普通业务使用现有 Node、HTTP、浏览器或迁移能力时，只改应用程序、声明、测试、评估和日志。新增通用执行能力或协议升级单独修改发布器并验证兼容候选。本次是一次性协议升级，须先交付发布器能力，再交付应用策略；本任务不执行游戏发布或生产探测。
