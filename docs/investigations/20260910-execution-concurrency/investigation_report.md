# 发布控制台交替进度调查

## 已确认的原因

2026-09-10 页面同时轮询任务 `1789009629878-4a0eb0f66b0ca8` 和 `1789009702762-1f1116097c9c3`。浏览器 Network 请求记录中，两条 `/api/jobs/` 链交替出现。持久化任务摘要分别显示最终运行校验和交付镜像，与用户两张截图一致。

原前端 `execute()` 仅清除已登记的计时器。已经发出的请求仍可在返回后调用 `renderJob()` 并建立新计时器。服务端 `createExecutionJob()` 无活动任务互斥，允许第二条发布任务启动。

## 修复及范围

前端增加提交锁、活动任务锁和响应归属检查。网络读取失败时自动重试当前任务。服务端在创建任务的同步入口拒绝活动任务及尚未清理的执行器，返回 HTTP 409。该检查在创建工作树和调用发布引擎之前执行，覆盖游戏和论坛。

发布流程、回滚决策、数据库迁移、生产任务的取消逻辑均未调整。现有任务继续执行。运行环境更新须等待所有既有任务结束。

## 验证边界

单元测试执行真实源码中的任务创建与前端异步函数，使用受控请求和延迟响应。浏览器使用真实 public 页面和隔离模拟 API；没有在生产 API 上测试重复发布。生产侧仅做状态读取，更新后的版本仍需现场验收。

Gemini `gemini-3.1-pro-high` 和 `gemini-3.6-flash-high` 图片请求均返回 `No available accounts`。外部视觉复核不可用，由主 Agent 检查真实浏览器截图完成视觉验证。
